# 简历导出换行错位问题总结

## 现象

- 图片 / PDF 导出时，flex 行内靠后的文本（user 模块的"X年经验"、工作经历条目的"岗位"等）被挤到下一行，与下方文字重叠。
- 浏览器屏幕预览正常，只有 snapdom 导出渲染时错位，且同一位置百分百复现。

## 根因

- 导出链路用 snapdom 将 DOM 克隆进 SVG foreignObject 渲染，过程中会把每个 flex 子项的 `getComputedStyle` 宽度取整后写死为内联样式。
- flex 容器的宽度按真实亚像素计算，而子项写死宽度之和按取整值累加，两者相差不足 1px（实测约 0.06px）时，`flex-wrap` 判定放不下，把行内靠后的子项换到下一行。
- 导出画布高度固定，换行后的文字绘制到下一模块区域，形成重叠。
- `reconcile` 只修正文本回流导致的宽度漂移，不处理 flex 子项宽度取整问题，因此图片导出开启 reconcile 后依然错位。

## 容易触发换行的写法

- flex-wrap 容器内有多个内容宽度的子项，且容器自身宽度由内容亚像素决定（如 `justify-between` + 内容驱动宽度的组合）。
- 行内子项宽度总和接近容器宽度，任一子项宽度取整后即溢出。
- Text 组件（外层 `relative min-w-0 max-w-full` + 内层 `w-full`）作为 flex 子项时，宽度写死后与容器出现亚像素差。

## 规避原则

- 信息容器撑满行内剩余宽度（`flex-1`），使容器宽度远大于内容总和，吸收子项宽度取整误差。
- 居中布局改为占满整行后内部居中（`w-full justify-center`），避免容器宽度由内容亚像素决定。
- 新增模块或字段时，避免"多字段并排 + flex-wrap + 内容驱动宽度"的组合。
- 新增主题时，字段行容器同样遵循上述宽度策略。

## 涉及位置

- user.vue：元信息行（性别 / 年龄 / 工作年限），主题差异已收敛到 `themeConfig` 配置表。
- expItemList.vue：条目信息行（名称 / 岗位 / 时间），影响工作、教育、项目经历等共用列表模块。
