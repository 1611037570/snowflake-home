# 简历分页几何契约

本文档约定预览分页链路的尺寸口径、数据含义与必须成立的不变量，是所有分页改动的验收依据。
它只描述已经落地的行为，不描述期望行为；与代码不一致时以本文档为准并同步修正代码。

代码阅读顺序：

```text
engine/adapter/buildLayoutNodes.ts（模块 → 通用排版节点）
  → engine/types.ts（节点与断点）
  → engine/layout/layoutTemplates.ts（页面区域与栏）
  → engine/measure/measureLayoutNodes.ts（真实 DOM 测量，唯一的尺寸来源）
  → engine/layout/regionFlows.ts（区域高度结算，纯函数）
  → engine/paginate/paginateFlow.ts（单栏贪心装箱，唯一的算法核心）
  → engine/paginate/pagePlan.ts（合并为预览、打印、导出共用的页面计划）
```

## 尺寸口径

| 量 | 含义 | 来源 |
| --- | --- | --- |
| 布局像素 | 未经 `transform: scale()` 的真实排版像素 | `measureLayoutNodes` 已按测量宿主自身换算回未缩放值 |
| 页面尺寸 | `794 × 1123` | `editor/preview/shared/constants.ts` |
| 页尾高度 | `PAGE_NUMBER_HEIGHT = 36` | 同上 |
| 整页可用高度 | `RESUME_HEIGHT − paddingVertical − max(paddingVertical, 页尾高度)` | `getContentHeight`，分页与「一页纸」共用同一公式 |
| 区域内容内边距 | 正文容器单侧内边距（`contentPadding`），同时扣高度与扣宽度 | `createResumeLayout` 与 `resolveColumnWidths` |
| 栏宽 | 比例栏按「内容宽 − 区域左右内边距 − 栏间距」再按比例分配 | `resolveColumnWidths`，与渲染层 flex 口径一致 |

区域高度结算（`regionFlows.ts`）按区域顺序累加首个页面已被占用的高度：

```text
首页可用高度(区域) = 整页可用高度 − 前面区域已占用高度 − 本区域上下内容内边距
后续页可用高度(区域) = 整页可用高度 − 本区域上下内容内边距
区域已占用高度(自适应) = 各栏首页 usedHeight 的最大值 +（首页有内容时再加上下内容内边距）
区域已占用高度(固定) = 区域配置高度，超出整页可用高度也不截断
区域已占用高度(剩余) = 整页可用高度
区域之间再叠加 regionGap（最后一个区域不叠加）
```

注意三条已经确定的边界行为：

- 区域高度结算只发生在**第一个页面**；后续页面各区域都按自身完整可用高度排版。
- 区域已占用高度取各栏首页 `usedHeight` 的最大值，栏与栏之间不互相等待。
- 区域顺序由 `order` 决定，调用方必须已排序；`regionFlows` 内不再排序。

## 节点与断点

| 字段 | 含义 | 产生方 |
| --- | --- | --- |
| `LayoutNode.type` | 节点类型（group / block / richText / repeat / media / spacer） | 模块适配器 |
| `LayoutNode.hideWhenPageLeading` | 落在后续页面首位时整块隐藏自身占位 | 段间距行 |
| `LayoutNode.title` | 模块标题节点，只在节点首次分片时渲染 | `attachModuleTitle` |
| `LayoutNode.breakPoints` | 声明式断点，仅用于渲染断点探针 | 富文本解析、经历条目 |
| `MeasuredNode.fullHeight` | 节点完整高度，块区间按**整块**计量，不会切进块内部 | 测量层 |
| `MeasuredNode.droppedTopSpacing` | 续段渲染时被移除的内容盒上内边距 | 测量层读 `paddingTop` |
| `MeasuredNode.breakPoints[].height` | 从节点起点到该断点的流内口径高度 | 测量层 |
| `MeasuredNode.breakPoints[].heightAtPageStart` | 同一断点的页首口径高度，已扣除页首渲染会移除的块上外边距 | 测量层 |
| `MeasuredNode.breakPoints[].blockEnd` | 块断点覆盖的块数量，区间为 `[0, blockEnd)` | 测量层读块结构 |
| `MeasuredNode.breakPoints[].leadingMargin` | 块上外边距，是页首口径的来源，分页层不再读取 | 测量层读 `marginTop` |

断点来自三条来源，合并顺序固定为「块断点 → 声明断点探针 → 行级文本断点」：

1. **块断点**：节点内声明了 `data-layout-block-range` 的容器的每个直接子元素，`blockEnd` 为块序号，高度按子元素底边到节点顶边计算。
2. **声明断点**：节点 `breakPoints` 在测量树中渲染的探针元素，高度为探针自身高度。
3. **行级文本断点**：声明了 `data-layout-split-lines` 的纯文本容器逐行上报偏移，用于描述类文本按行拆分。

测量层会过滤 `height <= 0` 的断点，块断点还会把 `offset` 固定为 `0`。

## 核心约定：页首口径与流内口径

同一个断点有两种高度，分页层按分片落在页面的位置选用：

- **流内口径** `height`：分片接在一段已有内容之后渲染，包含块上外边距、内容盒上内边距等全部留白。
- **页首口径** `heightAtPageStart`：分片落在页面首位渲染，渲染层会去掉该块上外边距；当「续段 + 内容盒已经开始」时，还会去掉内容盒上内边距。

两种口径的职责边界已经固定：

1. **块上外边距由测量层吸收**：测量块子元素时直接给出扣除 `marginTop` 的页首口径，分页层只做口径选择，不做几何扣减。
2. **内容盒上内边距由分页层按分片位置扣除**：它只在「续段落页首 + 内容盒已经开始」时被渲染层移除，这个条件依赖分片结果，属于分页层职责，读取 `droppedTopSpacing` 后按 `consumedBlocks` 与 `consumedOffset` 判断。
3. **缺省回退**：断点缺少 `heightAtPageStart` 时按流内口径处理，合成测量数据的用例因此保持原有口径。

任何改变渲染层留白规则的改动，都必须在测量层同步反映页首口径或 `droppedTopSpacing`，否则分页与渲染会静默错位。

## 必须成立的不变量

1. **分片不丢内容**：一次分页产生的全部片段合起来，必须完整覆盖节点内容；续段的起始偏移必须接在已消费内容之后。
2. **不重复渲染**：同一段内容不得同时被两个分片渲染。
3. **页首口径不超计**：落在页首的分片不得计入已被渲染层移除的留白。
4. **空页推进**：单页循环每轮要么消费内容、要么换页，不允许出现既不消费内容又不换页的轮次。
5. **可用高度非负**：所有可用高度与已用高度都不小于零。
6. **测量一致**：测量宿主必须与真实页面同宽度；分片的渲染结构必须与测量时的结构一致，块断点的序号才有意义。
7. **缩略图退化**：缩略图模式只过滤字符级断点，节点、块断点与行级断点必须与完整模式一致。
8. **回退可预期**：缺失测量结果时抛出错误，缺失断点时按剩余空间整片顺延，绝不允许溢出后循环不退出。

## 当前场景适配点

以下六处是分页层为了对齐渲染层留白规则所做的补偿，已由单测覆盖，改动前必须先补回归用例：

| 适配点 | 规则 | 覆盖用例 |
| --- | --- | --- |
| 续段顶部内边距 | 只在「续段落页首 + 内容盒已经开始」时扣除 | `续页扣除被移除的顶部内边距后继续填满当前页`、`内容盒首块已在前片渲染时，续段才扣除顶部留白` |
| 续段块上外边距 | 已上移到测量层：测量块子元素时给出扣除 `marginTop` 的页首口径，分页层只做口径选择 | `整片按页首口径计价，不再计入块上外边距`、`切割片段按页首口径计价，续段落在页首时不含块上外边距`、`当前页放得下媒体条目的首个内容块时不整条顺延` |
| 独立间距行 | 落页首时整块隐藏，高度按零计价 | `页面第一个内容不绘制间距占位，按去掉间距后的高度分页`（当前失败，见已知缺口） |
| 模块间距 | 下一个模块换页时，剩余空间仍放得下就留在页尾 `trailingGap` | `下一个模块换页时，模块间距落在上一页页尾` |
| 标题独立行 | 标题能放当前页就单独留下，正文顺延 | `正文放不下时标题与条目头留在当前页，正文顺延下一页` |
| 块与正文双轨 | 块断点只覆盖块，文本断点覆盖剩余全部块 + 正文区间 | `经历正文跨页后续页继续渲染正文块，不重复头部块` |

## 改动的顺序约束

1. 先补回归用例，再改几何口径；容器循环与装箱规则的改动必须用现有用例证明输出不变。
2. 分页算法只对「给定高度的一组定高槽位」做装箱，不认识区域、页尾、正文容器内边距；这些量在进入算法前必须折进可用高度。
3. 页首口径优先下沉到测量层：测量层用真实 DOM 能量出同一分片在两种渲染下的高度，分页层就不需要再推导减法。
4. 结构差异（时间轴、顶部通栏、外框模块）由适配器与主题声明编码，分页层不按模块 key 或主题编号分支。
5. 引擎层才需要单测，非引擎层不写测试用例。

## 已知缺口

以下问题在本次核对中确认存在，尚未修复，改动前请先补用例并明确取舍：

### 一、零推进护栏（已加保护，缺用例）

`blockCount` 按断点里的最大块结束序号统计，而测量层会过滤零高度块。两者不一致时，一次分片可能既不推进偏移也不推进块游标，单页循环会反复换页。`paginateFlow` 已加零推进护栏（游标全部没有前进时结束当前节点），避免循环不退出，但尚无对应用例。零高度块的真实来源是块高度恰好为零的渲染结构，极端测量结果下才会出现。

### 二、内容末尾的推导不可靠

`getContentEnd` 取断点序列**最后一项**的偏移，而块断点的偏移固定为 0。当块断点排在文本断点之后时，内容末尾会被低估成块断点之外的值，续段的起始偏移可能错误地回退到 0，导致同一段正文被两页重复渲染。首次分片选中块断点时，`contentRange` 为空会让该分片渲染整段富文本，与续段产生重叠。

需要修正的约定：内容末尾必须来自节点的真实内容长度（富文本节点解析结果里的 `textLength`），而不是断点数组的顺序。

### 三、内容盒上内边距仍由分页层推导

块上外边距已经上移到测量层（见「核心约定」）。剩下的内容盒上内边距，即 `droppedTopSpacing`，仍由分页层按 `consumedBlocks` 与 `consumedOffset` 判断后扣除，因为「续段 + 内容盒已经开始」这个条件只在分片结果确定后才成立。

`页面第一个内容不绘制间距占位，按去掉间距后的高度分页` 这条用例当前失败：续段落在页首、内容盒尚未开始渲染时，分页层没有按渲染层的口径扣除顶部留白，把 50 的内容算成 60，于是多出一页。这条用例自 `fix(resume-pagination): 修复段间距分页占位` 之后一直未被修复，属于已知回归。

修正方向是让测量层用真实分片 DOM 量出内容盒的页首口径，而不是继续在分页层增加减法分支。
