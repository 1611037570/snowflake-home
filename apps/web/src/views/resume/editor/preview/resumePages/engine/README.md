# 简历分页几何契约

本文档约定预览分页链路的尺寸口径、数据含义与必须成立的不变量，是所有分页改动的验收依据。
它只描述已经落地的行为，不描述期望行为；与代码不一致时以本文档为准并同步修正代码。

代码阅读顺序：

```text
engine/adapter/buildLayoutNodes.ts（模块 → 通用排版节点）
  → engine/types.ts（节点与断点）
  → engine/layout/layoutTemplates.ts（页面区域与栏）
  → engine/measure/measureLayoutNodes.ts（真实 DOM 测量，唯一的尺寸来源）
  → engine/layout/regionHeights.ts（区域内容高度与内容内边距，唯一的区域高度口径）
  → engine/layout/regionFlows.ts（区域高度结算，按栏下发每页可用高度）
  → engine/paginate/fragmentGeometry.ts（分片几何口径：块上外边距与顶部内边距的扣除规则）
  → engine/paginate/cutPoints.ts（切割点覆盖范围规则：块断点与文本断点各覆盖什么）
  → engine/paginate/paginateFlow.ts（单栏贪心装箱，唯一的算法核心）
  → engine/paginate/pagePlan.ts（合并为预览、打印、导出共用的页面计划）
```

## 尺寸口径

| 量           | 含义                                                               | 来源                                                                   |
| ------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 布局像素     | 未经 `transform: scale()` 的真实排版像素                           | 测量树挂在 body 上，处于缩放区之外，`getBoundingClientRect` 即布局像素 |
| 页面尺寸     | `794 × 1123`                                                       | `editor/preview/shared/constants.ts`                                   |
| 页尾高度     | `PAGE_NUMBER_HEIGHT = 36`                                          | 同上                                                                   |
| 整页可用高度 | `RESUME_HEIGHT − paddingVertical − max(paddingVertical, 页尾高度)` | `getContentHeight`，分页与「一页纸」共用同一公式                       |
| 区域留白     | 区域四周的内部留白（`RegionConfig.padding`），同时扣高度与扣宽度   | `createResumeLayout` 写入，`resolveColumnWidths` 与 `regionHeights` 读取 |
| 栏宽         | 比例栏按「内容宽 − 区域左右内边距 − 栏间距」再按比例分配           | `resolveColumnWidths`，与渲染层 flex 口径一致                          |

区域高度结算（`regionHeights.ts` 提供口径，`regionFlows.ts` 按区域顺序结算）累加首个页面已被占用的高度：

```text
首页可用高度(区域) = 整页可用高度 − 前面区域已占用高度 − 本区域上下内容内边距
后续页可用高度(区域) = 整页可用高度 − 本区域上下内容内边距
区域已占用高度(自适应) = 各栏首页 usedHeight 的最大值 +（首页有内容时再加上下内容内边距）
区域已占用高度(固定) = 区域配置高度，超出整页可用高度也不截断
区域已占用高度(剩余) = 整页可用高度
区域之间的间距由后一个区域的 gapBefore 表达，并在结算下一区域前计入首页已占用高度
```

区域之间的间距在渲染层是一个独立元素（两个区域盒子都不包含这段高度），因此区域自身的底色、轴线、底板都不会把它算进自己的绘制范围；它只作用于首页，后续页不会多出空白。

区域内容高度与内容内边距只在 `regionHeights.ts` 里定义一次，区域流结算与页面计划（`pagePlan.ts` 的溢出判定）都从这里读取，避免同一条公式在两层各写一遍而分叉。分页流的首页与后续页高度计划由 `paginate/pageHeights.ts` 独立维护。

图片作品由测量树与预览共用的 `render/imageWork.vue` 渲染：名称、描述使用条目完整宽度，图片水平居中；图片可用高度为正文区域后续页可用高度扣除说明高度、图文间距及条目上下内边距和边框。尺寸设置同时控制图片区域的宽高：百分之百使用完整条目宽度及图片可用高度，百分之五十使用二者的一半。图片通过 `object-contain` 在区域内等比放大或缩小，不受原图像素尺寸限制；整条作品在当前页放不下时整体顺延，不按页尾剩余空间缩小。说明文字自身超出整页时仍按真实高度报告溢出。

## 区域外观能力声明

跨层能力集中声明在主题文件的 `decisions`（固定能力）中，由 `themeDecisions.ts` 接入并校验；外观组件仅负责绘制，不再通过默认导出附带布局元数据。

页面边距由用户设置控制；区域之间的距离由公共模块间距控制；装饰容器与栏内的固定内边距由主题声明。三者分别结算，不互相覆盖。紫色履历的正文底板四周固定二十四像素属于装饰内边距，不进入用户配置。

| 字段 | 中文含义 | 使用约定 |
| --- | --- | --- |
| `regions.<槽位>.inset` | 区域内部四周装饰留白 | 上右下左完整声明；布局与公共区域容器共同读取，组件不重复施加 |
| `regions.user.fillsPageTop` | 个人信息背景覆盖纸张顶边 | 公共布局注入页面上边距，公共容器补足页面左右内缩 |
| `regions.main.columns` | 按左栏和右栏声明装饰内边距 | 使用语义栏位，不按数组长度猜测；仅双栏应用，由共用栏盒子施加 |
| `userContent.renderer` | 个人信息内容组件编号 | 接入层按版式提供公共默认组件，复杂主题显式声明 |
| `userContent.split` | 内容分片能力 | 整块组件忽略内部断点；稳定块组件才接收分片范围 |
| `usesDateRail` | 固定日期栏能力 | 条目与设置限制读取同一声明 |
| `restrictions` | 用户设置限制 | 主题集中提供限制原因，组件不再声明限制 |
| `topDecoration` | 首页独立装饰组件编号 | 独立于业务模块，真实高度只扣首页预算，续页不重复 |

栏外部宽度仍由公共比例与栏间距确定，内容宽度等于栏外部宽度扣除该栏左右装饰内边距。测量和预览共用 `render/columnBox.vue`，装饰空间只占用一次。单栏不应用为双栏声明的尺寸；栏内容宽度必须大于零，否则布局校验失败。

几何测试使用固定能力输入，验证四周留白、单侧留白、贴顶区域及栏装饰内边距等公共规则；所有真实区域外观遍历同一尺寸契约，不为主题名称编写独立期望值。

主题需要额外装饰留白时，在自己的主题定义文件中声明；布局、测量和渲染不允许按主题编号分支。**区域留白只表达区域内部的装饰空间**：留白里必须落得下被画出来的东西（底纹、色带、量尺基线、分隔线、底板内缩），纯粹为了让两个模块分开的空气留白一律不写。上下左右留白统一由公共容器施加，通栏页面边距也由公共容器结算。

装饰定位使用公共区域容器提供的变量：`--resume-region-inset-top`（区域顶部内部基准）、`--resume-region-inset-left`（区域左侧内部基准）、`--resume-column-gap-half`（栏间距中线）、`--resume-page-inset-horizontal`（页面水平边距）、`--resume-page-inset-vertical`（页面垂直边距）。装饰仍可维护自己的颜色、线宽与图案尺寸，禁止把公共几何写成固定像素。

顶部品牌文字与色带由 `pageDecoration`（页面独立装饰）绘制，不伪造业务标语节点、不参与空简历判断。隐藏树与预览使用同一装饰组件；字号、图片等变化触发实际高度重测，首页可用高度扣除此高度，续页恢复完整预算。用户真实标语继续作为普通业务模块渲染。

个人信息与正文第一个模块之间隔着一个区域边界，但这段距离仍然是**模块之间的距离**，因此由布局按模块上下间距统一补进正文区域的 `gapBefore`，与栏内模块间距同源同值、只作用于首页；主题不再用 `bottom` / `top` / `gapBefore` 声明这段间距。

个人信息默认独立成 `user` 区域并排在正文之前，单栏与顶部通栏单栏共用这一结构；只有左右布局把个人信息分进栏位时，它才作为栏内模块参与正文排版。该规则由布局模板入口统一决定，主题与外观组件都不需要声明。

页面上边距同样由布局统一注入，主题不得自行读取页面设置来声明它：顶部通栏区域（标语区域或声明了 `fillsPageTop` 的区域）覆盖纸张顶边，这份上边距就统一计入承载个人信息的区域的内部上留白，不产生任何区域外边距，通栏区域的底色也仍铺到纸张顶边。因此调整页面上边距时，个人信息与正文始终跟着移动。

注意三条已经确定的边界行为：

- 区域高度结算只发生在**第一个页面**；后续页面各区域都按自身完整可用高度排版。
- 区域已占用高度取各栏首页 `usedHeight` 的最大值，栏与栏之间不互相等待。
- 区域顺序由 `order` 决定，调用方必须已排序；`regionFlows` 内不再排序。

## 节点与断点

| 字段                                       | 含义                                                                   | 产生方                |
| ------------------------------------------ | ---------------------------------------------------------------------- | --------------------- |
| `LayoutNode.type`                          | 节点类型（group / block / richText / repeat / media / title / spacer） | 模块适配器            |
| `LayoutNode.hideWhenPageLeading`           | 落在后续页面首位时整块隐藏自身占位                                     | 段间距行              |
| `LayoutNode.breakPoints`                   | 声明式断点，仅用于渲染断点探针                                         | 富文本解析、经历条目  |
| `LayoutNode.splitMode`                     | 整块放置或按稳定块分片，未声明沿用既有断点规则                         | 主题内容接入层        |
| `MeasuredNode.fullHeight`                  | 节点完整高度，块区间按**整块**计量，不会切进块内部                     | 测量层                |
| `MeasuredNode.droppedTopSpacing`           | 续段渲染时被移除的内容盒上内边距                                       | 测量层读 `paddingTop` |
| `MeasuredNode.breakPoints[].height`        | 从节点起点到该断点的流内口径高度                                       | 测量层                |
| `MeasuredNode.breakPoints[].blockEnd`      | 块断点覆盖的块数量，区间为 `[0, blockEnd)`                             | 测量层读块结构        |
| `MeasuredNode.breakPoints[].leadingMargin` | 块前间距，续段首块渲染会移除它，分页计价据此扣除                       | 测量层读 `marginTop` 或网格块间距 |

断点来自三条来源，合并顺序固定为「块断点 → 声明断点探针 → 行级文本断点」：

1. **块断点**：节点内声明了 `data-layout-block-range` 的容器中参与正常排版的直接子元素，绝对定位与固定定位装饰不计入块序号；`blockEnd` 为块序号，高度按子元素底边到节点顶边计算，最后内容块包含节点底部留白。嵌套单列网格通过 `data-layout-block-index`（稳定块序号）声明字段边界，测量层读取真实底边和相邻块间距；隐藏头像或姓名时保留原块序号。双栏个人信息按该块区间跨页，续页不重复头像与姓名。
2. **声明断点**：节点 `breakPoints` 在测量树中渲染的探针元素，高度为探针自身高度，正文末尾断点使用节点完整高度以包含底部留白。
3. **行级文本断点**：声明了 `data-layout-split-lines` 的纯文本容器逐行上报偏移，用于描述类文本按行拆分。

测量层会过滤 `height <= 0` 的断点，块断点还会把 `offset` 固定为 `0`。

## 核心约定：页首口径与流内口径

同一个断点有两种高度，前者由后者按渲染层规则推导：

- **流内口径**：分片接在一段已有内容之后渲染，它的高度包含块上外边距、内容盒上内边距等全部留白。
- **页首口径**：分片落在页面首位渲染，渲染层会去掉该块上外边距；当「续段 + 内容盒已经开始」时，还会去掉内容盒上内边距。

`paginateFlow` **只接收流内口径的高度**，两类留白都由它在计价时扣除：

后续页是否处于内容起点按该栏实际已占用高度判断，前置零高度分片不打断页首。分页层将此结果通过分片的 `leadingOnPage`（实际页首标记）传到页面计划和渲染层；段间距隐藏共用这一标记，不再以分片索引判断。

```text
候选断点高度 = resolveCutHeight(切割点, 已消费高度, 是否首片, 顶部内边距)
分片高度     = resolveCutHeight(同一个切割点与同一组入参)
整片高度     = 剩余高度 − 下一个未消费块的上外边距（续段时扣除）
```

**这两行必须是同一个函数调用**：候选断点按计算出的高度比较、取最大者，分片高度取自同一结果。若只改变其中一处（例如只换分片高度的口径），排序结果会随之改变，可能选中与游标不一致的断点，导致分页把过多内容放进一页、页尾被挤出页面。

两条已经确定的边界：

1. **块上外边距与内容盒上内边距的扣除条件不同**：块上外边距在续段时无条件扣除（`middle` / `last` 装饰在页首与页中都不绘制）；内容盒上内边距只在「续段 + 内容盒已经开始」时扣除。
2. **扣除条件集中在 `fragmentGeometry.ts`**：`resolveCutHeight`、`resolveDroppedTopSpacing`、`resolveNextBlockMargin` 是这三条留白规则的唯一定义处，分页层只调用、不再自行做算术；改动留白规则只改这一个模块，并由 `fragmentGeometry.spec.ts` 锁定。

推导所需的两个量都来自测量层（`droppedTopSpacing` 与 `leadingMargin`），因此**任何改变渲染层留白规则的改动，都必须在测量层同步反映这两个量**，否则分页与渲染会静默错位。

## 必须成立的不变量

1. **分片不丢内容**：一次分页产生的全部片段合起来，必须完整覆盖节点内容；续段的起始偏移必须接在已消费内容之后。
2. **不重复渲染**：同一段内容不得同时被两个分片渲染。
3. **页首口径不超计**：落在页首的分片不得计入已被渲染层移除的留白。
4. **空页推进**：单页循环每轮要么消费内容、要么换页，不允许出现既不消费内容又不换页的轮次。
5. **可用高度非负**：所有可用高度与已用高度都不小于零。
6. **测量一致**：测量宿主必须与真实页面同宽度；分片的渲染结构必须与测量时的结构一致，块断点的序号才有意义。
7. **缩略图退化**：缩略图模式只过滤字符级断点，节点、块断点与行级断点必须与完整模式一致。
8. **回退可预期**：缺失测量结果时抛出错误，缺失断点时按剩余空间整片顺延，绝不允许溢出后循环不退出。

## 测量调度

测量是全链路里最贵的环节：一次测量要读上千次布局，宿主里每个断点探针都要参与。因此请求测量与执行测量分开：

- **同步作废**：数据、图谱或排版配置变化时立刻把测量结果标记为过期，分页在同一个 tick 内不会使用旧结果。
- **合并到一帧**：同一帧内的多次请求只执行一次测量；测量期间又发生变更时补测一次，保证最终结果对应最新内容。
- **只监听会改变测量的配置**：配置对象每次渲染都是新引用，深度监听会在一帧内被触发多次，因此按字段值比较（页边距、模块与段间距、字体四项、主题模板、布局类型、左栏宽度、正文容器内边距、字体版本）。

不要在测量宿主上挂子树变更监听：宿主里的 DOM 由 Vue 驱动，图谱监听已经覆盖，再叠加子树监听会让一次输入触发近十次重测量。

测量宿主、各排版节点和独立装饰同时观察尺寸变化：异步主题组件、标题或图片加载完成后，即使宿主仍被最小高度撑住，也按实际高度重新测量和分页。观察元素未更替时不重绑尺寸观察器，避免初始通知反复触发测量。

## 循环结构与收敛保证

单页装箱是两层循环，收敛性由这两条规则保证：

```text
外层（按页推进）：本页消费量没有前进时，才允许换页后重新进入内层
内层（填满当前页）：反复尝试放置，直到本轮消费了内容、或当前页已经换页
```

- 内层的退出条件同时看「消费量是否前进」与「当前页是否已经换页」，因此同一页不会被反复进入，也不会在同一分片上空转。
- 换页后允许重试，但同一节点连续换页且始终放不下内容的次数达到 `MAX_PAGE_TURNS_WITHOUT_PROGRESS` 时结束该节点，作为收敛的硬保证；此时该节点的剩余内容不会再输出。
- 空页有一条快路径：没有可选断点时允许放入整片（见下），因此「放不下」通常表现为溢出当前页，而不是无限换页。

## 放置决策

每个游标处只做一次决策，两条候选合成一条规则：

```text
整片候选：覆盖游标之后的全部内容，高度按同一口径预扣间距与下一个未消费块的上外边距
切割候选：只铺到某个断点为止，高度与覆盖范围都由该断点决定
选择：整片放得下就放整片，否则放能放下的最大断点；两者都放不下且当前页已有内容就换页重试
```

两个候选共用同一套试放与推进逻辑，差别只在高度来源与覆盖范围，不再各写一条放置路径。用例 `paginateFlowPlacement.spec.ts` 按五条路径（整片放下 / 改切 / 空页回退 / 间距页首隐藏 / 页尾间距）锁定可观测结果。

## 当前场景适配点

以下五处是分页层为了对齐渲染层留白规则所做的补偿，已由单测覆盖，改动前必须先补回归用例：

| 适配点         | 规则                                                                                       | 覆盖用例                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 续段顶部内边距 | 只在「续段落页首 + 内容盒已经开始」时扣除                                                  | `续页扣除被移除的顶部内边距后继续填满当前页`、`内容盒首块已在前片渲染时，续段才扣除顶部留白`               |
| 续段块上外边距 | 续段（`middle` / `last` 装饰）无条件扣除该块上外边距；扣除同时作用于候选断点排序与分片高度 | `当前页放得下媒体条目的首个内容块时不整条顺延`、`顶部间距块可以单独留在上一页，块区间 [0, 0) 不渲染内容块` |
| 独立间距行     | 落页首时整块隐藏，高度按零计价                                                             | `间距节点落页首隐藏占位，与内容一起顺延`                                                                   |
| 模块间距       | 下一个模块换页时，剩余空间仍放得下就留在页尾 `trailingGap`                                 | `换页时模块间距留在上一页页尾`                                                                             |
| 块与正文双轨   | 块断点只覆盖块，文本断点覆盖剩余全部块 + 正文区间；覆盖范围由 `resolveFragmentCut` 解析    | `经历正文跨页后续页继续渲染正文块，不重复头部块`、`resolveFragmentCut` 的规则用例                          |

标题不在适配点之列：它是 `type: "title"` 的**独立节点**，由适配器排在模块最前，分页层与普通块一视同仁，不再有"标题能否单独留页"的判断。模块标题与所属模块内容 `sourceModuleKey` 相同，因此两者之间不会插入模块间距。

## 改动的顺序约束

1. 先补回归用例，再改几何口径；容器循环与装箱规则的改动必须用现有用例证明输出不变。
2. 分页算法只对「给定高度的一组定高槽位」做装箱，不认识区域、页尾、正文容器内边距；这些量在进入算法前必须折进可用高度。
3. 页首口径目前由分页层推导，且**必须同时作用于候选断点排序与分片高度**：只把其中一处改成测量层给出的累计高度会改变排序结果并导致分页错位（见已知缺口五）。若将来要下沉到测量层，必须给出「从游标到断点」的高度差，而不是「从节点起点到断点」的累计高度。
4. 结构差异（时间轴、顶部通栏、外框模块）由适配器与主题声明编码，分页层不按模块 key 或主题编号分支。
5. 引擎层才需要单测，非引擎层不写测试用例。
6. 几何口径的改动必须用真实预览核对，不能只靠单测：单测只覆盖分页算法的输入输出，测量层与渲染层的口径一致性只有真实 DOM 能验证。

## 已知缺口

以下记录区分当前结构限制与已经修复的历史问题，改动前请先补用例并明确取舍：

### 一、异常测量输入的收敛诊断不完整

分页仍保留零推进护栏与换页上限。正常输入下，超高不可分内容通过空页完整接纳路径输出；不能将这一行为描述为正常内容被丢弃。对于自相矛盾的测量输入，当前尚缺独立诊断与覆盖完整性的统一上报，仍需作为协议边界检查。

`PagePlan` 已检查页面溢出及字符、稳定块的覆盖完整性，发现遗漏、重复或越界时返回无效计划和问题节点。`paginateFlow` 仍只返回页列表，没有独立返回异常收敛原因的通道。

### 二、超高不可分内容保留并上报溢出

整片与可推进断点都放不下时，有内容的页面先换页；空页保留完整剩余内容，再由 `PagePlan` 标记溢出。该规则优先保证内容完整，不将不可分的超高内容静默裁掉。异常测量输入下的收敛护栏仍缺专门的错误上报通道。

### 三、内容末尾的推导（已修复）

`contentEnd` 原先取断点序列**最后一项**的偏移，而块断点的偏移固定为 0：当块断点排在文本断点之后时，内容末尾会被低估成 0，续段的起始偏移随之回退到 0，首片又不携带正文区间，渲染层于是把整段正文渲染两遍。

现已改为读取测量层给出的 `contentLength`（正文真实字符长度），缺失时取断点偏移的最大值兜底，不再依赖断点数组顺序。回归用例见 `contentEnd.spec.ts`，它在旧实现下会失败。

### 四、内容盒上内边距仍由分页层推导（行为已修正）

内容盒上内边距，即 `droppedTopSpacing`，由分页层按 `consumedBlocks` 与 `consumedOffset` 判断后扣除，因为「续段 + 内容盒已经开始」这个条件只在分片结果确定后才成立。扣除条件已集中到 `fragmentGeometry.ts` 的 `resolveDroppedTopSpacing`。

原先记录的回归（`页面第一个内容不绘制间距占位，按去掉间距后的高度分页` 失败、把 50 的内容算成 60 多出一页）在「间距改为独立节点」时已随之修复，该用例现已通过。这里剩下的只是"口径由分页层推导而非测量层给出"这一结构事实，不再是缺陷。

### 五、块上外边距不能换成断点累计高度（已回退）

曾经尝试让测量层直接给出断点的页首口径 `heightAtPageStart = height − marginTop`，分页层改读该字段。这个改动**已回退**，原因是它把两件不同的事混成了一个字段：

- 候选断点排序与分片高度需要的是「从当前已消费高度到该断点的高度差」，扣除块上外边距后的 `height − marginTop` 满足这个语义；
- 而 `heightAtPageStart` 是「从节点起点到该断点的累计高度」，只在单个断点或首片场景下与前者数值巧合一致。多个断点候选时，用它排序会翻转最优候选，选中与游标不一致的断点，分页于是把过多内容放进一页。

真实后果：编辑器预览里内容盒高 1106px、可用高度 1065px，页尾被挤出页面 41px（`overflowY` 从 0 变为 41）。该回归当时通过了全部单测，只在真实预览核对时才暴露，因此留下这条记录与「改动顺序约束」第 6 条。

## 用户配置与主题固定外观

- `ui`（用户可编辑参数）只提供边距、间距、字号、内容展示及栏位排序，不包含主题固定版式、纸张边框、圆角和纹理。
- `themeDecisions`（当前主题固定外观）由预览入口独立传入分页链路；`layoutType`（页面版式）决定区域结构，`pageBorder.width`（边框宽度）参与可用宽高及测量签名计算。不得把这些字段重新合并到用户配置中。
- 页面外壳和主题组件读取预览上下文中的同一份主题决策，确保测量、分页及导出尺寸一致。

## 异步节点增高漏分页修复

- 回归用例先复现宿主高度不变时未监听内部节点尺寸的问题，补充节点尺寸观察后通过。
- 验证：测量、布局接线及分页相关九个文件共四十九项用例通过；导入简历首次加载与刷新均生成两页，标签和正文顺延且不重复，两页实际高度和滚动高度均为一千一百二十三像素。

## 空白续页修复

- 排除装饰边框的伪内容块，并让末尾断点包含底部留白，避免全部内容消费完后留下空尾片。
- 验证：回归用例修复前失败，修复后测量、布局接线及分页共五十项用例通过；真实预览刷新后第二页显示项目经历，两页滚动高度与页面高度均为一千一百二十三像素，主题顶端三角已移除。

## 通用装配与组件协议

- `contentKind`（内容语义）由业务适配器提供，公共渲染器按语义组件注册表选择；分页算法不读取它。节点复用签名包含该字段，避免语义变化后继续使用旧渲染组件。
- `ModuleAssemblyPolicy.title`（是否装配模块标题）与 `ModuleAssemblyPolicy.paragraphSpacing`（是否装配段间距）由适配器注册时声明。默认业务模块使用公共规则，个人信息与标语在自身注册处声明例外，不维护另一份业务名单。
- `RegionConfig.widthMode`（纸张或内容宽度模式）表达通栏几何，不按区域业务名称决定宽度。隐藏树与预览读取同一份区域配置，由公共区域和栏容器施加尺寸。
- `nodeFragment.vue`（节点外框）统一完整节点、分片探针与预览的外框选择和属性下发；`NodeContentProps`（正文标准输入）与 `useNodeContent`（分片内容读取）统一正文裁剪。主题覆盖仍使用公共分片协议。
- 测量签名包含全部区域及栏能力、个人信息内容能力、顶部装饰与日期栏能力，不只监听两处区域留白。
- 预览上下文提供 `layout`（公共引擎结算的区域与栏几何），图片等内容读取最终留白，不再读取主题原始留白另算预算。
- 页尾测量与预览共用 `pageFooter`（主题页尾外观入口），主题只能绘制固定槽位，不改写公共高度预算。
- 可见内容块由 `createContentBlocks`（公共块编号工具）登记，裁剪使用 `isContentBlockVisible`（公共范围判断）；显式稳定编号允许空号，但重复、逆序及非法编号不能进入分页。
- `validateFragmentCoverage`（通用输出覆盖检查）读取同一份节点、测量与各栏分片，检查字符和实际块的遗漏、重复与越界。正文续页重复块由字符轨道判断，页首隐藏间距允许不输出；无效计划沿用既有错误展示入口。
- 正文先按字符切过后，末尾块断点只覆盖剩余字符并同步推进正文游标，避免整段正文再次渲染。头部块断点仍不消费正文字符。

完整主题职责、覆盖目录与验收规则见 [主题设计规范](../../../../theme/README.md)。
