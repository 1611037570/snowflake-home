# 简历字段变更须知

改动简历的任何业务字段时，必须同步范本数据，否则模板卡片与字段核对会失效。以下两条约定对所有改动者（含 AI）生效。

## 一、字段口径的唯一定义处

业务字段由表单配置声明，字段契约由它生成：

| 用途 | 位置 |
| --- | --- |
| 字段声明（key、标签、组件、字典、校验） | `apps/web/src/stores/modules/resume/config/formConfig.ts` |
| 字段契约生成 | `apps/web/src/views/resume/editor/assistant/resumeSchemaRegistry.ts` |
| 模块与字段的契约文案（供模型与导入使用） | `apps/web/src/views/resume/editor/assistant/skills/skill_resume_data_contract.ts` |

**判断某个字段是否存在，以 `formConfig.ts` 为准**，不要以范本数据为准。

## 二、修改任何字段 → 必须同步范本

范本数据位于 `apps/web/src/views/resume/template/data/resumes/`，每个文件是一份可套用的简历数据，同时被模板卡片缩略图与全屏预览消费。

字段发生下列任一变化时，必须检查并更新**受影响的范本文件**：

| 变更类型 | 需要做的同步 |
| --- | --- |
| 字段重命名 | 所有含该字段的范本文件，以及模板文案键 `resumeTemplateContent_<fileName>_*` |
| 字段取值调整（字典项变化） | 使用该字段的范本取值要改成合法值，避免落到已删除的选项 |
| 字段移除 | 所有范本中删除该字段 |
| 字段新增 | 见下一条 |

范本文件与模板卡片的对应关系在 `apps/web/src/views/resume/template/data/list.ts`，卡片文案在 `apps/web/src/locales/lang/zh/resume.json` 与 `en/resume.json` 的 `resumeTemplateContent_<fileName>_*`。

## 三、新增字段 → 必须同步全字段范本

`resumes/recommended/allFields.ts`（卡片名「全字段简历」）是**字段完整性基准**：它覆盖全部模块与全部业务字段，用来核对新字段的展示效果。

**新增任何业务字段后，必须在该文件中补上对应取值。**

不作同步的后果：新字段在范本中缺失，模板预览看不到它的渲染效果，字段回归问题无法通过范本核对发现。

## 四、如何自查是否漏同步

在浏览器控制台（开发环境）执行：

```js
const registry = await import("/src/views/resume/editor/assistant/resumeSchemaRegistry.ts");
const data = await import("/src/views/resume/template/data/resumeData.ts");
const sample = await data.loadResumeTemplateData("allFields.ts");
// 逐个模块比对该模块声明的字段是否都在 sample.data[模块] 中有非空取值
```

预期结果：**每个模块都没有缺失字段**。若出现缺失，说明新增字段未同步到全字段范本。

## 五、模板数据的三类不变式

1. **模块齐全**：`allFields.ts` 必须覆盖字段契约里的全部模块（含自定义模块）。
2. **字段非空**：`allFields.ts` 里每个已声明字段都要有非空取值。
3. **引用完整**：`list.ts` 的每个 `fileName` 都能在 `data/resumes/` 下找到同名文件；两个语言包的 `resumeTemplateContent_<fileName>_*` 与 `resumeTemplateStyle_<id>_*` 文案键齐全，不得出现原始键名。

## 六、简历 AI 功能与迭代约定

### 当前功能入口

简历助手位于 `editor/assistant/`，目录内的 `README.md` 说明文件职责。新增或调整现有 AI 能力时，须同步本节，避免入口、技能与实际行为出现迭代差异。

| 功能 | 当前行为 |
| --- | --- |
| 简历生成 | 选择已有模块并描述事实，避免重复新增；缺失事实使用待补充占位，不编造经历 |
| 简历优化 | 按整体结构、语言表达或内容润色优化当前读取范围 |
| 一键优化 | 收集求职方向与身份；局部选择时先取得整份读取授权，再补齐有事实依据的经历、优化并输出六维报告 |
| 简历翻译 | 翻译当前读取范围的内容与模块标题；完整写入成功后同步展示语言 |
| 岗位对标 | 收集岗位描述，支持仅分析或分析后直接写入两种模式 |
| 简历评估 | 读取整份简历，输出体检问题与六维评分 |
| 打招呼语 | 按正式、亲切或幽默风格生成正文，不写入简历 |
| 职业规划与人生总结 | 读取整份经历生成正文，不写入简历 |
| 智能导入 | 支持 Markdown 与 PDF；PDF 在浏览器逐页转图片、Markdown 读取文本后直接调用解析模型；共用响应检查、字段兼容转换、待补充提示与预览确认后创建；个别字段转换失败仅提示，不拦截其他内容，完全无有效内容时不创建简历 |
| 正文字段快捷处理 | 对当前字段生成、润色或精简，沿用编辑器历史撤销；保留请求期间的手动编辑 |
| 面试辅助 | 由 `editor/assistant/interview/` 维护流程、建议卡片与技能，在简历助手中合并入口 |

### 读取与写入约束

- `useResumeAssistant.ts` 是工具与技能的唯一组装入口；常驻提示由 `skills/registry.ts` 注册，任务与行业技能通过按需工具加载。
- `flows.ts` 维护引导步骤和建议卡片；每次基于简历作答或修改均须重新读取真实数据，不复用上一轮的数据。
- `resumeContext.ts` 默认读取所选模块，未选择时读取整份简历；字段快捷处理通过 `resumeModuleKeys`（本轮固定读取的模块标识列表）指定当前模块与求职方向；流程通过 `resumeScope`（本次请求的简历读取范围）设为 `all`（整份简历）固定本轮范围，请求结束后清除。
- AI 读取仅返回 `title`（模块展示标题）与 `data`（模块业务数据），数组记录不携带编辑器状态；稳定模块键用于写操作，展示标题不能代替模块键。
- 媒体字段以 `stores/modules/resume/config/mediaFields.ts` 为准，只从读取副本中移除头像与作品图片；读取、请求开始与请求结束均不得删除或临时改写原简历媒体。
- 脱敏模式处理姓名、电话与邮箱，严格模式额外处理工作和教育名称；模型必须保留隐私标记，不猜测真实内容；含标记字段保持只读，不把隐私标记写回真实简历。
- `propose_resume_edits` 校验字段契约后提交完整语义操作列表，写入立即生效并支持会话内撤回；校验失败不写入，执行部分失败时重新读取最新数据，仅重试未成功操作。
- 翻译展示语言切换须有本轮完整写入成功凭据，不得用语言切换代替翻译写入。
- 一键优化最终输出一个 `resume-report` 报告，固定六维为信息完整度、阅读效率、职业契合度、职业成就、发展潜力、职业稳定性；无判断基础的维度使用空值，总分为有效维度均分四舍五入，改动清单仅记录实际成功操作。

### 迭代同步清单

- 调整能力入口：核对 `flows.ts`、建议卡片、`skills/registry.ts`、`skills/prompt_default.ts` 中的任务分派与对应技能正文。
- 调整字段或格式：同步表单配置、生成的数据契约、写入校验与受影响范本，新增字段遵循本文件的全字段范本约定。
- 调整读取范围、脱敏或媒体字段：核对 `resumeContext.ts`、请求生命周期与撤回逻辑，确认首次及重复读取不携带媒体、不修改源数据。
- 调整写入或翻译：核对工具描述、校验、领域执行结果、失败重试与本轮语言切换凭据。
- 调整评分或报告：同步评分技能、一键优化技能与 `resumeReport.ts` 的解析约束。
- 每次完成一轮修改后，在本目录记录实际变更与验证结果，并单独提交；非引擎层不新增测试用例。

### 全面检查：请求与撤回

- 请求备份改为响应式数据可用的序列化副本，保留完整记录及媒体，避免原生深拷贝代理对象抛错，也避免删除或排序撤回时图片下标错配。
- 工具加载后与实际执行前均检查请求版本、简历和会话；取消或切换后不再启动旧请求，也不执行旧请求的简历工具。
- 撤回入口仅在工具确认实际写入且内存备份仍存在时显示；校验失败、历史会话和已撤回回复不显示无效入口。
- 翻译撤回同步恢复请求前展示语言；撤回成功后才提示成功。
- 验证：人工运行核验响应式备份、工具加载期取消、失效工具隔离、媒体与展示语言恢复、重复撤回均通过；差异格式检查通过。

### 全面检查：读取、脱敏与写入校验

- 固定本轮模块选择与脱敏等级，避免生成过程中调整选项影响已启动请求；旧任务结束不会清除新任务上下文。
- 普通脱敏补齐个人敏感字段整体保护，电话格式不符合手机号正则时仍隐藏；严格脱敏同时处理正文及标题中的公司、学校名称，空名称保留为空，避免误判为已填写。
- 写入校验拒绝隐私标记及受保护字段修改，避免脱敏内容覆盖真实内容；需要修改受保护字段时关闭脱敏后重试。
- 整批操作按执行顺序模拟记录变化，支持新增后继续修改，同时拒绝删除后的失效下标；模拟不修改真实数据。
- 起草未知日期与富文本允许留空，只有结束时间允许“至今”；未知日期及枚举不使用文本占位，普通文本仍可使用待补充占位。
- 补齐空新增记录、空操作数组、伪段落标签和非有限数字校验，同步编写提示与数据契约。
- 验证：相关已有用例 15 项通过；人工核验顺序下标、新增后修改、日期与富文本、隐私写入保护、范围与等级冻结、正文严格脱敏、原数据保留均通过；差异格式检查通过。

### 全面检查：引导、续轮与会话隔离

- 引导期间输入只推进当前步骤，选择步骤仅接受有效选项；拒绝授权后不发起请求，运行或加载期间禁止重复启动与消息撤回。
- 新启动的逐题面试将 `interviewFlow`（面试流程标识）写入用户消息上下文，续轮继承整份读取范围，历史话题恢复对应的快速回答、提前结束和语音入口；提前结束清除流程标识但保留收尾所需的读取范围。此前未记录流程标识的历史消息不推测流程类型。
- 会话切换清除未完成的本地引导；快速回答返回时检查所属简历和话题，旧结果不进入新会话；旧草稿异步保存完成不覆盖后来切换的简历或话题。
- 重试仅针对当前轮，已产生写入时先撤回；历史写入备份失效时阻止直接重试或重新生成，避免重复新增和删除。
- 真实写入标记在工具成功后记录，撤回后清除；请求中止或出错后，已经发生的写入仍可撤回。
- 从零生成仅列出已有记录数组模块，排除个人信息、社交账号等不适合经历起草的模块；面试介绍移除没有验证依据的命中率与入职率承诺，建议时限与实际能力保持一致。
- 验证：已有会话、面试流程、请求范围、快速回答用例共 23 项通过；人工核验选项防绕过、面试续轮范围、入口恢复、提前结束、无备份重试保护均通过；差异格式检查通过。

### 全面检查：评分报告与目录说明

- 报告解析校验六个固定维度的名称、顺序与整数评分范围，问题级别、改动清单和文本清单均按实际结构校验；兼容旧报告缺失的可选清单。

- 仅移除有效报告代码块，普通 JSON、无效报告及未完成流式内容保留；前面的无效块不阻断后续有效报告。
- 按实际代码入口修正助手目录依赖说明，补齐报告职责并修正全字段范本已迁移到推荐子目录的路径。

### 全面检查：字段契约与技能一致性

- 补齐编辑区原先仅检查模型可用性的生成、润色、精简按钮，实际处理当前正文；通过表单公开字段路径定位模块与记录，不按正文内容猜测目标。
