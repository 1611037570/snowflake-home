# 独立 AI 简历优化

工作台 `optimize/index.vue` 选择简历，编辑器的一键优化直接带入当前简历；两类入口通过 `resume-open-optimize` 事件打开 `aiResumeOptimizer.vue`，由简历布局统一按需挂载。

- `useResumeOptimization.ts`：创建固定简历副本，复用编辑器写入能力、助手脱敏上下文与长上下文压缩，执行一次任务；用户点击“保存”时才按编号写回并保存，不创建聊天消息或持久化会话。
- `resumePreview.vue`：复用正式分页渲染器展示全部简历页，按可用宽度缩放；工作台展示所选简历，优化结果弹窗默认只展示报告，不挂载简历。点击“查看简历”后隐藏报告、展示优化后简历；点击“查看对比”后隐藏报告、同时显示优化前后，按弹窗实际可用宽度自动并排或上下排列，不提供版本切换；可随时返回报告，预览不跳转、不修改纸张排版参数。
- `optimizationReport.vue`：默认只渲染具体问题、改动说明、改善点、可选评分与待补充项，不展示前后摘录或改动对比清单；程序仍根据最初原简历与最终草稿生成净改动，模型只补充说明，报告格式不阻断内容结果。未完成时隐藏评分，明确展示部分结果。
- 保存前原简历保持不变，放弃或关闭丢弃草稿；保存时遇到内容或结构变化则拒绝覆盖。
- 手动停止或失败时保留已完成字段校验的有效修改，标明尚未完成整份复核；可预览、保存部分结果或从草稿继续，继续失败仍保留之前的结果。失败或异常的写入批次整体回滚，避免留下半条记录。关闭、放弃或离开页面丢弃未保存草稿。
- AI 请求与专用任务规则维护在 `@snowflake/resume-agent`，页面不直接请求模型。任务保留真实读取、写入和修改后复核的公共契约，由 Agent 按目标选择写作、匹配和评估方法，不固定工具步骤。补写候选沿用共用规则，未知细节使用 XX，保存前须核实。
- 页面、弹窗与 Agent 执行入口共用本地内容检查：只有姓名、岗位、联系方式或空模块时不发起模型请求，直接提供填写/生成入口；已有任一真实经历、技能或优势即可优化，不要求所有模块齐全。
- 页面、报告、弹窗统一采用 `p-3` / `gap-3`，不增加大间距、营销卡片或限制页面宽度的居中外壳。
- 表单、优化报告、完整简历预览与改动详情弹窗统一使用 `SfScrollbar`；弹窗内容使用 `flush` 复用外壳留白，简历预览保留滚动条内置 `px-3`，内容只补纵向间距，不重复叠加横向内边距。
- 按仓库规范未运行构建、测试或浏览器验证。
