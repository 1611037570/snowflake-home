# 公开页面预渲染

公开页面沿用原有组件和布局。首页、模板库、小舟人工智能、求职指南、求职工具及工具详情、求职统计和通用设置不再额外插入搜索介绍区。范本详情保留自身的公开范本正文。

## 维护入口

| 文件 | 职责 |
| --- | --- |
| Web 根目录 `site.config.ts` | 页面标题、摘要、收录属性、预渲染开关与页面层级 |
| `page.ts` | 构建与客户端共用的标签、规范地址和结构化数据解析 |
| `catalog.ts` | 首批公开范本的固定地址与源文件对应关系 |
| `content.ts`、`publicContent.vue` | 仅范本详情的公开段落展示，不向其他页面插入介绍 |
| `scripts/publicPages.ts`（Web 根目录下） | 输出独立页面头部、预渲染清单与范本共享数据模块 |
| `scripts/prerender.mjs`（Web 根目录下） | 在隔离浏览器中运行原有页面，保存实际渲染内容与对应样式 |
| `scripts/exampleSections.ts`、`scripts/seoHead.ts`（Web 根目录下） | 公开范本字面量提取与统一头部模板 |

调整界面直接修改原有页面组件，不维护另一套搜索正文。调整标题与收录属性修改页面配置。新增公开页面时，在业务路由登记组件，并在页面配置中声明 `prerender`（是否预渲染原页面）；禁止收录的页面不参与预渲染。`schemaType`（结构化数据类型）、`parentRoute`（直接上级地址）和 `applicationCategory`（应用用途分类）的中文含义与取值在配置类型旁维护。

## 构建流程

普通 Web 构建命令仍为 `pnpm --filter @snowflake/web build`，也可沿用根目录的构建命令。

- Vite 先输出应用资源、各路由头部和 `seo-prerender.json`（公开页面预渲染清单）。
- 构建后脚本只向本机提供本次产物，逐页运行原有应用，等待公开布局、页面标题与首批加载完成，再保存实际界面内容。
- 每页使用全新的浏览器上下文，不读取开发者已有浏览器数据。只允许本机产物请求，阻止外部模型、访客统计及其他服务请求。静态产物不含用户投递记录、模型密钥或目录授权。
- 页面渲染失败时构建失败，不回退成另一份介绍文字。已经生成的压缩网页同步更新。
- 开发服务不写入静态产物，正常显示原有界面。哈希路由构建不进行独立页面预渲染。

产物仍位于仓库根目录 `dist/web`。例如小舟页面为 `dist/web/resume/ai/index.html`。浏览器加载后由原有客户端应用接管，用户配置与工具交互仍在运行时读取。

## 构建机准备

安装项目依赖后，首次为构建机安装浏览器：

```sh
pnpm --filter @snowflake/web exec playwright install chromium
```

Linux 构建机缺少浏览器系统依赖时，可使用 Playwright 的 `install --with-deps chromium` 安装方式。已安装兼容 Chromium 的构建机可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`（浏览器可执行文件路径）复用现有安装。预渲染只在打包阶段运行，不需要部署常驻渲染服务。

## 范本维护

范本正文通过 `virtual:resume-public-sections`（公开范本段落模块）提供给独立详情页。范本源文件可放在范本目录的子目录中，文件名保持唯一；提取默认导出对象的 `data`（公开范本内容）字面量，不执行主题代码。缺失、重名或空正文会明确报错。

## 部署

沿用根目录 `deploy/nginx-resume.conf` 的独立文件优先规则。服务器复制完整的 `dist/web` 产物，未知范本地址返回不存在状态。首次合并服务器规则后，后续页面和正文更新只需重新打包部署。

站点地图根据页面配置生成。禁止收录通过网页中的禁止索引指令声明；预渲染和提交链接本身不保证收录或排名。
